# PocketStudio

Мини-аналог Android Studio, который работает на самом телефоне.

- **Редактор кода**: вкладки, дерево файлов, подсветка Kotlin/Java/Gradle/XML/JSON, отмена/повтор, автоотступ, панель символов.
- **Сборка debug/release APK и release AAB** настоящим Gradle (внутри Termux), с подписью вашим ключом.
- **Ключи и SHA**: создание keystore, SHA-1/SHA-256/MD5 из `.jks`/`.keystore`/`.p12`, из любого APK, из debug-ключа Gradle и через `gradle signingReport`.
- **Установка и отправка** готовых файлов прямо из приложения.

## Как это устроено

PocketStudio не пытается втиснуть Gradle в своё приложение. Редактор, ключи и SHA работают сами по себе,
а сборку приложение поручает **Termux** (через его интерфейс `RUN_COMMAND`): там ставятся JDK 17, aapt2 под Android,
Gradle 8.7 и Android SDK, и запускается обычный `gradle assembleDebug / assembleRelease / bundleRelease`.

Общая папка: `/storage/emulated/0/PocketStudio`

    projects/    ваши проекты (сюда можно положить чужую папку Android-проекта)
    keystores/   ключи подписи
    output/      готовые .apk и .aab
    logs/        журнал и состояние текущей задачи
    .scripts/    ps.sh и init.gradle (приложение обновляет их само)

Подпись release-сборок подставляется init-скриптом Gradle: проект править не нужно. Если проект сам задаёт
подпись в `build.gradle`, используется его настройка.

## Первый запуск

1. Установите **Termux из F-Droid или с GitHub** (версия из Google Play не подходит).
2. Откройте PocketStudio → вкладка **«Настройка»** и пройдите шаги 1–6:
   доступ ко всем файлам → разрешение запуска команд в Termux → команда настройки в Termux →
   «Проверить» → «Установить» инструменты (1–1,5 ГБ, 10–30 минут, лучше по Wi-Fi и на зарядке).
3. Вкладка **«Проекты»** → «Новый проект» → вкладка **«Сборка»** → «Собрать».

Первая сборка проекта дольше обычных: Gradle скачивает Android Gradle Plugin и зависимости.

## Как собрать сам PocketStudio, если компьютера нет

Нужен репозиторий на GitHub с этими файлами. После загрузки откройте вкладку **Actions → «Сборка PocketStudio» → Run workflow**:
готовый `app-debug.apk` будет в артефактах запуска. Подойдёт и любая среда, умеющая открывать Gradle-проекты
(Android Studio, AndroidIDE и т.п.): проект стандартный, Gradle wrapper 8.7 уже лежит рядом.

## Что проверено, а что нет

Проверено автоматически (на JVM, Gradle 8.7 и bash):

- разбор JKS и PKCS12, отпечатки SHA-1/SHA-256/MD5 совпадают с `keytool`; созданный приложением keystore читается `keytool`;
- логика редактора (отмена/повтор, автоотступ, вставка), работа с папками и шаблонами проектов;
- контракт Intent с Termux по исходникам Termux (`com.termux.RUN_COMMAND`);
- `ps.sh` целиком (установка, сборка, копирование результата, коды ошибок) на подставных `pkg`/`curl`/`gradle`;
- init-скрипт Gradle на настоящем Gradle 8.7 (подпись release, отключение lint).

**Не проверено**, потому что в среде разработки не было Android SDK и устройства:

- сборка самого приложения (Compose-экраны писались без компилятора Android: возможны мелкие ошибки, при первой сборке
  пришлите текст ошибки — это обычно правка одной строки);
- реальный запуск Gradle/AGP в Termux на телефоне (aapt2 и JDK из Termux, `android.aapt2FromMavenOverride`).
  Ошибки покажутся в журнале на вкладке «Сборка», там же есть кнопка «Копировать журнал».

## Известные ограничения

- Только Gradle-проекты Android; один открытый проект за раз; подсветка на регулярных выражениях, без подсказок кода и без отладчика.
- Файлы больше 1,5 МБ в редакторе не открываются.
- `MANAGE_EXTERNAL_STORAGE` и запуск команд в Termux не пройдут проверку Google Play: приложение рассчитано на установку APK напрямую.
- Пароли keystore живут только в памяти приложения, но в момент сборки передаются в Termux аргументами команды.
